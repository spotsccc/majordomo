# Повторный анализ: архитектура и стек Majordomo

Объект: [personal-agent-architecture.md](personal-agent-architecture.md), срез источников от 5 сентября 2026. Дата ревью: 30 сентября 2026.

Методика. Все URL, процитированные в документе, проверены HTTP-запросами. Ключевые утверждения сверены с исходным текстом страниц, README и npm-реестра. Версии и даты релизов взяты из `registry.npmjs.org` и GitHub API. Всё, что ниже помечено как «инженерная оценка», — вывод ревьюера, не подтверждённый источником. Прототипы по-прежнему не разворачивались.

## 1. Вердикт

**Рекомендацию нужно пересмотреть.** Каркас исходного документа остаётся в силе: разделение жизненных циклов, протокол изменяющих операций, модель памяти, HealthKit-синхронизация, критерии проверки runtime. Пересмотреть нужно выбор «Eve + PostgreSQL Workflow world» как единственного первого кандидата.

Факты, изменившие картину:

1. **Postgres world официальный, но это эталонная реализация (reference implementation).** README пакета: _«not a managed backend: it ships without authentication, and it is not tuned for the performance or scale»_. Для production Vercel предлагает форкнуть и адаптировать. Получается, что самый критичный слой, долговечное состояние агентных запусков, опирается на наименее зрелый компонент стека. [README world-postgres](https://github.com/vercel/workflow/tree/main/packages/world-postgres), [workflow-sdk.dev/worlds/postgres](https://workflow-sdk.dev/worlds/postgres).
2. **Версии совместимы только через beta-ветку.** Eve требует линию `@workflow/* 5.0.0-beta`. Тег `latest` у `@workflow/world-postgres` указывает на 4.3.7, несовместимую с Eve. Нужная версия есть только под тегом `@beta` (5.0.0-beta.48 от 29.09). Postgres world включается ключом `experimental.workflow.world`. [Eve self-hosting](https://github.com/vercel/eve/blob/main/docs/guides/deployment/self-hosting.md).
3. **Eve меняется очень быстро.** С 6 по 28 сентября вышло 35 релизов, с 0.52.2 до 0.68.0. Среди них несколько ломающих изменений:
   - 0.57: изменилась семантика steering;
   - 0.63: `defineWorkflowTool` обязателен для durable background tools;
   - 0.65: изменён формат `ctx.ask()`;
   - 0.66: изменены экспорты `eve/client`;
   - 0.67: убран run mode и `outputSchema`, сессия теперь всегда паркуется после хода.

   Проверку «обновление версии при незавершённой задаче» исходный документ ставит седьмым пунктом прототипа. На деле она становится вопросом еженедельной эксплуатации. [Releases](https://github.com/vercel/eve/releases).

4. **Исследование пропустило альтернативу, прямо отвечающую требованиям.** DBOS Transact TS — MIT-библиотека долговечных процессов поверх собственной PostgreSQL, без отдельного сервера. Проверенные возможности:
   - durable sleep;
   - `send/recv` и `setEvent/getEvent` для ожиданий;
   - очереди с лимитами;
   - cron-расписания, хранимые в БД;
   - пакет `@dbos-inc/vercel-ai` для AI SDK v7, с `durableCalls` и `durableTools`.

   Версия 5.2.11 от 29.09. [README](https://github.com/dbos-inc/dbos-transact-ts), [интеграция с AI SDK](https://docs.dbos.dev/integrations/vercel-ai).

**Что предлагается вместо этого.** Прототип по тем же восьми критериям провести на двух вариантах и ограничить его по времени:

- **A. AI SDK v7 + DBOS + своя PostgreSQL.** Долговечное состояние лежит в той же БД, что и данные приложения, под зрелой лицензией и без экспериментальных ключей. Каналы, протокол стриминга, HITL-запросы и sandbox придётся писать самим.
- **B. Eve на закреплённой версии.** Нужно проверить два world: Postgres world (`@beta`) и локальный world на постоянном диске (`.eve/.workflow-data`). Зрелость локального world для production не проверялась. Вариант выигрывает, если готовые сессии, HITL, NDJSON-поток и sandbox экономят заметно больше кода, чем стоит сопровождение беты.

Зрелость DBOS проверялась тем же способом, что и зрелость Eve:

- **Ядро `@dbos-inc/dbos-sdk`** выходит почти каждую неделю. Мажорная версия 5.0 вышла 16.09: миграция схемы, удалены устаревшие интерфейсы, есть [migration guide](https://docs.dbos.dev/typescript/upgrading). В 4.25 встроенный admin server объявлен устаревшим и по умолчанию выключен. [Releases](https://github.com/dbos-inc/dbos-transact-ts/releases).
- **`@dbos-inc/vercel-ai`** ещё до 1.0 и тоже быстро меняется: 0.1.5 (07.07) → 0.2.5 (16.09) → 0.3.7 (19.09) → 0.4.4 (24.09).
- **Повторы.** Модельные вызовы и tools оборачиваются в шаги DBOS. Документация прямо говорит, что прерванный model call перезапускается. По модели шагов прерванный tool, видимо, тоже выполнится повторно, но явной формулировки для tools на странице нет. Retries по умолчанию выключены. Идемпотентность изменяющих операций остаётся задачей приложения, как и в Eve. [Интеграция](https://docs.dbos.dev/integrations/vercel-ai).

Инженерная оценка: у ядра A зрелая модель хранения, и оно не зависит от экспериментальных ключей. Но слой интеграции с агентом у A так же молод, как Eve. Поэтому предпочтения до прототипа нет. Решающие вопросы прототипа: сколько кода A потребует на каналы, HITL и стриминг и насколько болезненно B переживает обновления.

## 3. Пробелы в рассуждении

### 3.1. Меняют решение

1. **Пропущен класс альтернатив «durable execution как библиотека».** Исследование сравнивает Eve с двумя крайностями: pg-boss (слишком низкий уровень) и Temporal (тяжёлая эксплуатация). Середина не рассмотрена:
   - **DBOS**: PostgreSQL, MIT, интеграция с AI SDK. Самый прямой кандидат.
   - **Restate**: зрелая модель durable promises и AI SDK middleware. Минус — отдельный stateful-сервер со своим хранилищем вместо PostgreSQL, лицензия BSL, но собственное использование разрешено. [docs](https://docs.restate.dev/ai)
   - **Mastra 1.x**: TS-фреймворк агентов с `PostgresStore`. Восстановление активных запусков после рестарта в production исправлено только 22.09 ([PR #24663](https://github.com/mastra-ai/mastra/pull/24663)). Одна связанная ошибка открыта ([#25365](https://github.com/mastra-ai/mastra/issues/25365)).
   - **LangGraph.js**: `PostgresSaver` и `interrupt()`, но только checkpoint графа; планировщика нет.
   - **Inngest self-hosted**: сервер под SSPL, AgentKit обновляется редко (последний релиз — ноябрь 2025).
2. **Сетевая граница сервера не спроектирована.** Документ подразумевает публичный reverse proxy с TLS. Для одного владельца с финансовыми и медицинскими данными это архитектурное решение, а не деталь эксплуатации. Дополнительный аргумент: README Postgres world предупреждает, что `POST /.well-known/workflow/v1/flow` не проверяет вызывающего, и советует закрыть этот маршрут снаружи. Self-hosting doc Eve при этом велит проксировать весь префикс `/.well-known/workflow/`, иначе запуски зависают. Префикс относится к маршрутизации Workflow SDK, поэтому та же проблема, вероятно, есть и у локального world. Это не проверено, и считать её особенностью только Postgres не стоит. Инженерная оценка: держать клиентов и API в приватной сети (WireGuard или Tailscale) и открывать наружу только узкий вход для webhooks с проверкой подписи. Tailscale Funnel умеет последнее, но сам в beta ([kb](https://tailscale.com/kb/1223/funnel)).
3. **Клиенты привязаны к протоколу runtime.** В начале документ требует независимости клиентов, а в разделе «Клиенты» предлагает им работать напрямую с HTTP/NDJSON-протоколом Eve. Если прототип отвергнет Eve или протокол сломается в очередном минорном релизе (как в 0.66), придётся переписывать и web, и mobile. Минимальная мера — свой тонкий контракт событий и команд на сервере, а на клиенте адаптер.
4. **Нужен платный Apple Developer Program.** С бесплатным Personal Team provisioning profile на устройстве истекает через 7 дней, а Push Notifications (APNs) недоступны. HealthKit и Background Modes в таблице capabilities для бесплатного уровня отмечены. Отдельной строки для HealthKit background delivery там нет, так что его доступность на бесплатном уровне не проверена. Без платного членства план с push на iPhone не реализуем. [Compare memberships](https://developer.apple.com/support/compare-memberships/), [capabilities](https://developer.apple.com/help/account/reference/supported-capabilities-ios). Для Mac уведомления можно получать через Web Push в Safari или в веб-приложении, добавленном в Dock: нативное приложение и платный аккаунт не нужны ([WebKit](https://webkit.org/blog/12945/meet-web-push/)). Это усиливает выбор PWA для Mac.

### 3.2. Меняют план, но не выбор стека

5. **Аутентификация одного владельца и устройств не описана.** Нужно решить:
   - как регистрируется новое устройство;
   - каким механизмом входить (passkey, долгоживущий device token);
   - как отозвать доступ потерянного iPhone;
   - как аутентифицируется Mac companion и чем ограничены его capabilities.

   HITL в Eve позволяет задать политику, кто вправе одобрять запрос. Её нужно связать с идентичностью устройства.

6. **Не описано, как хранятся секреты и как их восстанавливать.** Восьмой пункт прототипа упоминает «ключи доступа», но не говорит, как шифруются OAuth-токены интеграций в БД, где лежит мастер-ключ и как он попадает в резервную копию. Если ключ лежит рядом с копией, шифрование бесполезно; если ключ не в копии, её нельзя восстановить.
7. **Не учтена политика хранения данных у LLM-провайдеров.** Минимизация промптов описана, но выбор провайдера и режима важен не меньше: срок хранения, использование для обучения, zero-data-retention. Категории «здоровье» и «финансы» разумно разрешать только моделям и аккаунтам с подходящей политикой.
8. **Нет оценки поведения агента.** Упоминание «проверять изменения на примерах» недостаточно. Нужен небольшой регрессионный набор:
   - извлечение фактов в память (что сохранено, что помечено как гипотеза);
   - точность проактивных уведомлений (лишние и пропущенные);
   - выбор инструментов и соблюдение политик.

   Eve переносит evaluate-API между модулями (0.60, 0.62), так что этот слой тоже лучше держать своим.

9. **Prompt injection — это проблема потока данных, а не только проверки действия.** Документ проверяет права перед внешним эффектом. Но опасна сама комбинация трёх вещей:
   - доступ к личным данным;
   - недоверенный контент (письма, страницы, результаты MCP);
   - канал наружу (отправка сообщения, HTTP-запрос браузера, ссылка в уведомлении).

   Инженерная оценка: после чтения недоверенного контента запуск нужно помечать. Для помеченного запуска исходящие каналы ограничиваются или требуют решения, даже если само действие по правилам разрешено.

10. **Sandbox работает на одном хосте с БД и credentials.** На единственном сервере Docker-контейнер браузера и произвольного кода соседствует с PostgreSQL и секретами. Инженерная оценка: для недоверенного исполнения нужна отдельная VM или microVM, либо хотя бы отдельный пользователь, сеть без доступа к БД и отсутствие Docker socket. С 0.64 Eve описывает sandbox через provider environments; проверить это на закреплённой версии.
11. **Недооценён риск повторного выполнения.** Если batching model calls в Eve включён, при сбое повторяются и tool calls из пачки (см. строку 2 таблицы). Протокол operationId в документе это покрывает, но прямое требование нужно добавить: `modelCallsPerStep` не включать, пока все изменяющие tools не идемпотентны.

### 3.3. Вопросы без готового ответа

12. **Два UI-стека.** Документ предлагает React web для Mac и React Native/Expo для iPhone. Expo поддерживает web через react-native-web, так что один код мог бы обслуживать оба клиента. Цена — ограничения web-вывода RN. Решить после первых экранов.
13. **Наблюдаемость.** В 0.54 Eve сменил схему трейсов с v3 на v4 и удалил часть span. Дашборды на трейсах runtime будут ломаться при обновлениях. Метрики из раздела «эксплуатация» лучше строить по своим таблицам (задачи, операции, доставки).
14. **Форма документа.** В исходнике нет markdown-заголовков, разделы выделены жирным текстом. Навигация и ссылки на разделы затруднены.

## 5. Что не проверено

- Зрелость локального (дискового) Workflow world для production и то, открыт ли у него flow-эндпоинт так же, как у Postgres world.
- Реальная совместимость DBOS с агентным циклом AI SDK: проверена только документация интеграции, код не запускался. Не подтверждено, повторяется ли прерванный tool-шаг.
- Доступность HealthKit background delivery на бесплатном Apple-аккаунте.
- Поведение всех вариантов под сбоями. Это по-прежнему задача прототипа.
- Политики хранения данных конкретных LLM-провайдеров.

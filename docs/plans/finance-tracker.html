План: финансовый трекер

Статус: готов к разработке
Как владелец, который держит деньги в фиате и крипте в разных кошельках, я хочу записывать траты, переводы и обмены сообщением боту и править учёт на страницах, чтобы в любой момент знать остаток каждого кошелька, сколько у меня всего в одной валюте и сколько я потратил за период.

1Задача

Владелец держит деньги в фиате (RUB, USD, ARS, GEL) и крипте (USDT, USDC, BTC, ETH) в разных местах. Ему нужен один учёт, который сходится с реальными кошельками до последнего знака, отвечает «сколько я потратил» и «сколько у меня всего» и ведётся сообщениями боту.

Путь сценария шаг за шагом

Схема последовательности по UML: участники сверху, время идёт вниз. Сообщение идёт только от вызывающего к вызываемому, ответ возвращается тем же путём. Рамки — фрагменты: в alt выполняется одна ветка, в par — все сразу.

синхронный вызовасинхронное сообщениевозвратalt — ветки по условию в [ ]par — ветки идут одновременнокрасный текст — ошибка, возвращается значением

Тулы агента

Пишущие тулы возвращают сохранённую транзакцию и новые остатки затронутых кошельков: агент сразу называет, что записал и какой стал остаток. Ожидаемые сбои (NotFoundError, ValidationError, InsufficientFundsError) тул возвращает значением { error: { code, message } }; неожиданная ошибка базы — код internal и console.error.

    Пункт Ответ Что меняется в плане
    1. Тул и многошаговый ход работает: шаг 1 кончается finish-step с tool-calls, SDK выполняет тул, шаг 2 отвечает текстом; каждый шаг — отдельный запрос, тело сжато zstd SSE для codexToolCall — таблица ниже
    2. Параллельные вызовы приходят: 5 запусков из 5 — два function_call в одном ответе, строго подряд, дельты не перемешиваются; оба execute стартуют одновременно, результаты — в порядке вызовов, затем один finish-step ничего
    3. Два потока одного хода fullStream и toUIMessageStream читаются в одном Promise.all без зависаний. Колбэк — onEnd (onFinish — устаревший алиас); не дочитанный UI-поток его не вызывает Э4: onEnd; сбой — по onError, не по outcome (таблица ниже)
    4. Telegram склейки нет: Chat SDK ставит \n\n между шагами. Но во время тулов висит начало первой фразы — схема ниже Э4: обёртка над fullStream в handlers.ts
    5. CoinGecko Demo-ключ работает; лимит — 30 запросов в минуту, а не 100; у 429 с ключом тело — текст Throttled лимит в плане исправлен; Э3 различает ошибки по статусу

    Что видит владелец в Telegram во время тулов (п. 4)

    SSE вызова тула (п. 1) — по ней пишется фейк Э4

    Событие Что в нём
    response.created, response.in_progress ответ целиком, output: []
    response.output_item.added output_index; item { type: "function_call", id: "fc_…", call_id: "call_…", name, arguments: "", status: "in_progress" }
    response.function_call_arguments.delta × N item_id, delta — кусок JSON (то по токенам, то целиком)
    response.function_call_arguments.done arguments — весь JSON
    response.output_item.done item с arguments и status: "completed"
    response.completed output: [] — транспорт его не читает

    Текст до вызова — первым item (message, output_index 0), вызовы — следующими; рассуждение — item reasoning перед ними. Второй запрос: в input сообщение владельца, текст первого шага (role: "assistant", output_text), если он был, все function_call, затем все function_call_output с output: [{ type: "input_text", text: <JSON результата> }]. Reasoning обратно не отправляется. В запросе parallel_tool_calls: true, store: false, тулы — { type: "function", name, description, parameters, strict: false }.

    Сбой после выполненного тула (п. 3)

    Случай onError хода onEnd responseMessage
    второй запрос — HTTP 500 Codex request failed with HTTP 500 outcome: "completed", finishReason: "error" тул в output-available и пустой step-start
    abort() после execute ошибка отмены outcome: "aborted", isAborted: true тул в output-available

    outcome не отличает сбой модели от успеха, поэтому сбой определяется, как сейчас: по onError и отказу thread.post. Частичное сообщение с выполненными тулами есть и при сбое, и при отмене. Транспорт 500 не повторяет.

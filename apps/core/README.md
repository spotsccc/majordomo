# @repo/core

Сервер ассистента на Next.js 16 (App Router), деплоится на Vercel. Принимает запросы агента, отвечает моделью OpenAI по подписке ChatGPT и сам поддерживает эту подписку в рабочем состоянии. Ведёт учёт денег владельца: агент записывает траты по сообщениям, а страницы `/finance` показывают и правят учёт в браузере.

## Вход владельца

- **Браузер.** Владелец вводит токен `MAJORDOMO_API_TOKEN` на `/login` и получает httpOnly-cookie `majordomo_session` на 400 дней. Без неё `/` и `/finance` ведут на `/login`. «Выйти» в навигации удаляет cookie. Значение cookie — HMAC от токена, поэтому смена токена выводит из всех браузеров.
- **Клиенты API** шлют заголовок `Authorization: Bearer $MAJORDOMO_API_TOKEN`. Ручки принимают и cookie, но запрос на запись с cookie проходит только с того же Origin.
- Без входа владельца работают `/api/health`, cron-ручки (`Authorization: Bearer $CRON_SECRET`) и вебхук Telegram (секрет `TELEGRAM_WEBHOOK_SECRET`).

## API

| Ручка                          | Что делает                                                                                                |
| ------------------------------ | --------------------------------------------------------------------------------------------------------- |
| `POST /api/agent`              | ход агента: `{ messages: UIMessage[] }` → поток UI-сообщений AI SDK (совместим с `useChat`)               |
| `POST /api/openai/login`       | начать вход в ChatGPT или вернуть уже начатый: `{ verificationUrl, userCode, expiresAt, pollIntervalMs }` |
| `GET /api/openai/login`        | проверить, ввёл ли владелец код: `{ state: "pending" \| "complete" \| "none" \| "failed" }`               |
| `GET /api/openai/status`       | состояние сессии: `logged_out`, `active` или `reauth_required`                                            |
| `POST /api/openai/logout`      | выйти и отозвать refresh-токен                                                                            |
| `GET /api/cron/openai-refresh` | Vercel Cron раз в сутки продлевает сессию (`Authorization: Bearer $CRON_SECRET`)                          |
| `GET /api/cron/finance-rates`  | Vercel Cron раз в сутки записывает курсы валют из CoinGecko                                               |
| `POST /api/telegram/webhook`   | вебхук Telegram-бота                                                                                      |
| `GET /api/health`              | проверка живости                                                                                          |

## Вход в ChatGPT с клиента

1. Клиент отправляет запрос в `/api/agent`.
2. Если сессии ещё нет или она умерла, сервер отвечает `409`:

   ```json
   {
     "error": "openai_login_required",
     "message": "Вход в ChatGPT не выполнен.",
     "login": {
       "verificationUrl": "https://auth.openai.com/codex/device",
       "userCode": "ABCD-1234",
       "expiresAt": "…",
       "pollIntervalMs": 5000
     }
   }
   ```

3. Клиент показывает ссылку и код. Владелец открывает ссылку (можно на том же телефоне), входит в ChatGPT и вводит код.
4. Клиент раз в `pollIntervalMs` вызывает `GET /api/openai/login`, пока не получит `complete`, и повторяет исходный запрос. При `failed` (код отклонён) клиент запрашивает новый код через `POST /api/openai/login`.

Так работает и минимальный веб-чат на `/`: он открывается после входа владельца, показывает ссылку и код при `409` и после входа в ChatGPT повторяет сообщение.

Пока код действует (15 минут), повторные запросы получают тот же код. Дальше сессия продлевается сама: токен обновляется при запросах и раз в сутки по cron.

## Финансы

Учёт ведётся в кошельках: у кошелька остатки в нескольких валютах, фиатных и крипто. Транзакции четырёх видов:

| Вид           | Что делает с остатками                                                                             |
| ------------- | -------------------------------------------------------------------------------------------------- |
| трата         | списывает сумму и комиссию; у траты всегда есть категория                                          |
| пополнение    | зачисляет сумму                                                                                    |
| перевод       | списывает сумму и комиссию с одного остатка и зачисляет на другой; в том же кошельке — обмен валют |
| корректировка | зачисляет или списывает без категории; так записываются и начальные остатки кошелька               |

Что важно знать:

- Остаток не бывает меньше нуля: трата или перевод сверх остатка не записываются.
- Удаление транзакции мягкое: удалённую можно восстановить. Кошелёк и категория не удаляются, а уходят в архив. Кошелёк без транзакций удаляется совсем.
- Суммы хранятся и складываются как десятичные строки без округления (`numeric(38,18)`), число знаков ограничено валютой.
- «Вчера», «в сентябре» и границы месяца считаются в часовом поясе `OWNER_TIME_ZONE`, по умолчанию UTC.

**Как вести.** Сообщением агенту в Telegram или в веб-чате («потратил 3500 песо на кофе с наличных»): агент вызывает тулы учёта (`src/lib/finance/tools.ts`) и отвечает, что записал и какой теперь остаток. Или на страницах:

| Страница                     | Что на ней                                                                             |
| ---------------------------- | -------------------------------------------------------------------------------------- |
| `/finance`                   | «Всего» в выбранной валюте, кошельки, траты месяца по категориям, последние транзакции |
| `/finance/transactions`      | список с фильтрами по кошельку, виду, валюте, периоду и заметке; удалённые             |
| `/finance/transactions/new`  | форма транзакции; сумму можно ввести как «3 500,50»                                    |
| `/finance/transactions/[id]` | правка, удаление и восстановление                                                      |
| `/finance/wallets/new`       | новый кошелёк с валютами и начальными остатками                                        |
| `/finance/wallets/[id]`      | остатки, транзакции кошелька, новая валюта, переименование, архив                      |
| `/finance/categories`        | траты месяца по категориям, новая категория, переименование, архив                     |
| `/finance/currencies`        | справочник валют с последним курсом; новая фиатная валюта или монета из CoinGecko      |

**Курсы.** Cron раз в сутки (04:37 UTC) берёт из CoinGecko цену каждой валюты в долларах. Если курса дня нет, берётся последний до него. «Всего» считается по курсам сегодняшнего дня UTC, а валюта без курса называется отдельно. `COINGECKO_API_KEY` (Demo-ключ) необязателен: без него действует бесплатный лимит без ключа. Новая фиатная валюта добавляется кодом ISO 4217, криптовалюта — выбором монеты среди найденных в CoinGecko по тикеру: у одного тикера бывает много монет.

Код: доменный модуль `src/lib/finance/` (`finance-store.ts` — запись и чтение, `money.ts` — схемы сумм и транзакций, `rates.ts` — курсы), страницы `src/app/finance/`, таблицы — схема `finance` (`packages/db/src/schema/finance.ts`). Подробности и правила — в [плане](../../docs/plans/finance-tracker.html).

## Локальный запуск

Локально Postgres работает в Docker (`compose.yaml` в корне). Адреса базы в `.env.example` уже указывают на него.

```sh
cp apps/core/.env.example apps/core/.env.local   # заполнить ключ и токены: openssl rand -base64 32
pnpm dev                                         # из корня: Postgres в Docker, миграции, затем dev-серверы
```

`pnpm dev` по очереди выполняет `pnpm db:up` (поднять Postgres и дождаться готовности), `pnpm db:migrate` и `turbo run dev`. Если Docker не запущен, команда сразу падает. Эти шаги можно запускать и по отдельности.

`pnpm db:migrate` и `drizzle-kit` (`db:studio`) читают адрес базы из `apps/core/.env.local`. Переменные, заданные в окружении, важнее файла. `pnpm db:down` останавливает контейнер, данные остаются в томе. Удалить и данные: `docker compose down -v`.

Как устроены база, миграции и секреты и что нужно для первого деплоя, описано в [docs/architecture/database.md](../../docs/architecture/database.md).
